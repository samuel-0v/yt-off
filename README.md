# yt-off

Initial project structure for a local-only web application managed with Docker.

## Stack

- Frontend: React, Vite, TypeScript, Tailwind CSS, React Router
- Backend: Go with Fiber
- Runtime: Docker Compose
- Prepared dependencies: Docker SDK for Go and SQLite

## Services

- `frontend`: Vite development server on port `5173`
- `backend`: Fiber API on host port `18080`
- `yt-dlp`: isolated container with `yt-dlp` and FFmpeg installed

## Getting Started

```bash
docker compose up --build
```

For local-network use, prefer the helper script. It detects the host LAN IP, updates `.env`, and starts Docker Compose:

```bash
./scripts/up.sh
```

After startup:

- Frontend: `http://localhost:5173`
- Backend health: `http://localhost:18080/health`
- Backend version: `http://localhost:18080/api/version`
- Storage info: `http://localhost:18080/api/storage`
- Docker status: `http://localhost:18080/api/docker/status`
- Video formats: `POST http://localhost:18080/api/formats`
- List downloads: `GET http://localhost:18080/api/downloads`
- Create download: `POST http://localhost:18080/api/downloads`
- Download status: `GET http://localhost:18080/api/downloads/{id}`
- Cancel download: `DELETE http://localhost:18080/api/downloads/{id}`
- List files: `GET http://localhost:18080/api/files`
- Download file: `GET http://localhost:18080/api/files/{name}`
- Delete file: `DELETE http://localhost:18080/api/files/{name}`

Downloaded files are written to the local `downloads/` directory in this project. The containers mount it at `/downloads`.
Download tasks are stored in SQLite at `/app/data/yt-off.db` inside the backend container, backed by the `database` Docker volume.

```bash
curl -X POST http://localhost:18080/api/formats \
  -H "Content-Type: application/json" \
  -d '{"url":"https://demo.unified-streaming.com/k8s/features/stable/video/tears-of-steel/tears-of-steel.ism/.mpd"}'
```

The response returns friendly `options` prepared from the raw `yt-dlp` formats. It does not start a download.

To create a download task:

```bash
curl -X POST http://localhost:18080/api/downloads \
  -H "Content-Type: application/json" \
  -d '{"url":"https://media.w3.org/2010/05/sintel/trailer.mp4","format_id":"mp4"}'
```

While running, `GET /api/downloads/{id}` returns in-memory progress fields such as `progress`, `speed`, `eta`, and `filename`.

The `/downloads` frontend route shows persisted history and files available in the local downloads directory.
Downloads are queued with a default limit of 2 simultaneous tasks. Queued and running tasks can be cancelled.

The settings page shows the detected local-network URL and a QR Code for opening yt-off from another device on the same network.

YouTube cookies cannot be generated by yt-off. They are authentication cookies created by your browser after you sign in. The app supports importing a Netscape `cookies.txt` file through the settings page; automatic browser-profile import would require explicitly mounting browser profile directories into Docker and should be enabled only with care.

## YouTube Cookies Tutorial

Use this when YouTube shows bot verification, sign-in confirmation, or rate-limit errors.

Recommended flow using the browser extension `Get cookies.txt LOCALLY`:

Official installation links:

- Chrome Web Store: https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc
- Firefox Add-ons: https://addons.mozilla.org/firefox/addon/get-cookies-txt-locally/
- Source code: https://github.com/kairi003/Get-cookies.txt-LOCALLY

1. Open YouTube in the browser where you normally use your account.
2. Confirm that you are signed in and that the video opens in the browser.
3. Click the `Get cookies.txt LOCALLY` extension icon.
4. Export cookies for the current site, preferably `youtube.com`, in Netscape `cookies.txt` format.
5. Save the file as `cookies.txt` or `youtube.txt`.
6. Open yt-off, go to `Configurações > Cookies do YouTube`, and upload the file.
7. Return to Home and analyze the video URL again.

Important notes:

- The file should start with `# Netscape HTTP Cookie File`.
- Do not use JSON or CSV exports.
- Do not share the file. Cookies can grant access to your browser session.
- If YouTube asks for verification again later, export a fresh `cookies.txt`.

This stage intentionally does not implement websocket progress streaming, authentication, or advanced settings.
